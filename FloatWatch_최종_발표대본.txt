(슬라이드 1 · 표지)

안녕하십니까. / 3조 발표를 시작하겠습니다. /

저희가 개발한 FloatWatch는 / 현장 영상에서 해양 부유물의 위치와 종류를 AI로 식별하고, /
탐지 결과와 성능 지표를 / 이후 대응에 활용할 수 있는 기록으로 관리하는 AI 분석 워크스페이스입니다. /

지금부터 / 해양쓰레기 관측 과정에서 어떤 문제를 발견했고, /
이를 서비스 기능과 AI 모델 학습으로 어떻게 해결했는지 말씀드리겠습니다. /


(슬라이드 2 · 목차)

발표 순서입니다. /

먼저 조원 소개와 프로젝트 일정, / 프로젝트를 기획한 배경과 수요를 설명드리겠습니다. /
이후 시스템 구조와 주요 기능, / 네 개 AI 모델의 학습 개선 과정과 최종 비교 결과를 말씀드리고, /
실제 서비스 시연과 향후 확장 계획 순으로 발표하겠습니다. /


(슬라이드 3 · 조원 소개)

저희 팀을 소개하겠습니다. /

조장 이지건은 / 프론트엔드와 백엔드 개발을 담당했습니다. /
부조장 노형래는 / 데이터베이스와 인프라 구축, 프로젝트 문서화를 담당했습니다. /

허유진 조원은 / 데이터셋 구성과 YOLOv8s, YOLO11s 파인튜닝을 담당했고, /
이승연 조원은 / 데이터셋 구성과 YOLO26s, RT-DETR-L 파인튜닝을 담당했습니다. /

각자 맡은 영역을 개별적으로 개발하는 데 그치지 않고, /
서비스 개발부터 AI 모델 학습까지 / 하나의 흐름으로 연결했습니다. /


(슬라이드 4 · 프로젝트 일정)

프로젝트 일정입니다. /

1주차와 2주차에는 / 프로젝트 목표와 탐지 클래스를 선정하고, /
데이터셋 수집, 프론트엔드·백엔드·데이터베이스 MVP 구축, / 1차 AI 모델 학습을 진행했습니다. /

3주차에는 / 사용자별 대표 PT 등록·관리 기능을 추가하고, /
동일한 미디어를 네 개 모델로 일괄 분석하는 구조를 구현했습니다. /
모델별 바운딩 박스와 클래스, 성능을 비교하고 / 탐색 기록 상세 화면도 개편했습니다. /

4주차에는 / 네 종류 AI 모델을 추가 학습하고 동일 검증셋 기준으로 성능을 비교했습니다. /
또한 실시간 탐지 기능과 / 위치 지도, 탐지 증거 기록 기능을 연동했습니다. /

5주차에는 / 전체 기능과 예외 상황을 통합 테스트하고, /
시연 데이터와 발표 시나리오, 최종 모델과 발표자료를 정리했습니다. /
현재 계획한 1주차부터 5주차까지의 주요 목표는 모두 완료했습니다. /


(슬라이드 5 · 프로젝트 개요)

다음은 프로젝트 개요입니다. /

저희는 해양 부유물 관측의 문제를 / 환경, 사회, 기술의 세 관점으로 정리했습니다. /

환경 측면에서는 / 해양 부유물이 생태계와 연안 환경을 지속적으로 위협하고 있습니다. /
사회 측면에서는 / 한정된 인력과 시간으로 넓은 해역을 반복 관측하기 어렵습니다. /
기술 측면에서는 / 수작업 영상 판독과 분산된 기록이 분석 효율을 떨어뜨립니다. /

그래서 FloatWatch는 / AI로 영상 속 부유물의 위치와 종류를 빠르게 식별하고, /
탐지 결과와 성능 지표를 하나의 기록으로 통합해 /
환경 대응을 위한 판단 근거를 만드는 것을 목표로 했습니다. /


(슬라이드 6 · 수요 조사)

다음은 수요 조사입니다. /

해양수산부 자료에 따르면 / 연간 해양쓰레기 발생량은 약 14만 5천 톤이며, /
경제 피해는 약 4천억 원, / 선박 추진기 감김 사고는 연평균 378건으로 제시되고 있습니다. /

2024년에는 수거·처리와 발생 예방 등에 / 약 1,547억 원의 국비가 투입됐습니다. /
또한 인천광역시는 / AI와 드론을 활용한 해양환경관리 사업에 약 70억 원을 투자해 /
탐지와 수거 경로 최적화를 추진했습니다. /

이 수치들은 해양쓰레기 문제가 일시적인 현상이 아니라, /
지속적인 관측과 관리, 효율적인 대응 체계가 필요한 문제임을 보여줍니다. /
따라서 부유물의 위치와 종류를 빠르게 확인하고 / 결과를 누적해 활용할 수 있는 분석 시스템이 필요하다고 판단했습니다. /


(슬라이드 7 · 기술 스택 및 시스템 아키텍처)

다음은 시스템 아키텍처입니다. /

프론트엔드는 Next.js와 TypeScript로 구성해 / 서비스 화면과 모델별 결과를 시각화했습니다. /
백엔드는 FastAPI와 SQLAlchemy를 사용해 / 인증, 분석 자산 관리와 네 개 모델의 분석 묶음을 처리합니다. /

AI 추론 영역에서는 Ultralytics와 OpenCV를 활용해 /
등록된 대표 모델로 이미지와 영상 프레임을 분석하고 바운딩 박스를 생성합니다. /
파일 스토리지에는 모델, 미디어와 결과 파일을 저장하고, /
SQLite에는 계정, 대표 PT, 분석 묶음과 성능 지표를 저장합니다. /

전체 분석 흐름은 / 대표 PT와 미디어 준비, 모델·미디어 검증, 등록 모델 순차 추론, /
모델별 결과와 지표 저장의 네 단계로 동작합니다. /


(슬라이드 8 · 기능 소개)

주요 기능은 / 업로드 기반 분석과 실시간 탐지, 두 가지 흐름으로 구성했습니다. /

먼저 업로드 기반 분석입니다. /
사용자는 네 모델별 대표 PT를 지정하고 / 분석할 이미지나 동영상을 등록합니다. /
분석을 시작하면 동일한 미디어를 등록된 대표 모델들이 일괄 분석하며, /
일부 모델이 등록되지 않은 경우에는 해당 모델만 제외하고 분석을 계속합니다. /

분석이 끝나면 모델 탭에서 바운딩 박스와 클래스를 확인하고, /
클래스별 탐지 수와 신뢰도, 전체 탐지 수와 처리 속도를 비교할 수 있습니다. /
결과는 하나의 분석 묶음으로 저장되며 / 탐색 기록에서 다시 조회할 수 있습니다. /

두 번째는 실시간 탐지입니다. /
브라우저 카메라를 연결하고 / 관측 지점과 위치 정보를 함께 등록할 수 있습니다. /
적용할 모델을 선택하면 / 카메라 프레임에서 클래스, 신뢰도와 바운딩 박스를 실시간으로 확인할 수 있습니다. /
탐지 시간과 위치, 클래스, 신뢰도와 증거 이미지는 세션 단위로 저장되어 / 이후 기록에서 다시 확인할 수 있습니다. /

이외에도 공지사항, 자유게시판, FAQ, 1대1 문의와 안내 챗봇, /
회원 권한·이용 상태, 분석 로그, 문의 답변과 관리자 감사 로그 기능을 구현했습니다. /


(슬라이드 9 · AI 리포트 A — YOLOv8s·YOLO11s 학습 개선 과정)

다음은 YOLOv8s와 YOLO11s의 학습 개선 과정입니다. /

각 차수는 이전 가중치를 이어받는 방식이 아니라, /
앞선 결과에서 확인한 문제를 데이터 구성과 학습 조건에 반영해 / 독립적으로 다시 학습한 실험입니다. /

1차 학습에서는 / 11개 클래스, 총 18,710개의 불균형한 기본 데이터로 기준 성능을 확인했습니다. /
클래스별 객체 수가 196개에서 7,064개까지 차이가 나 / 클래스 간 성능 편차가 나타났습니다. /

2차 학습에서는 / 두 모델의 데이터 분할과 입력 크기, 옵티마이저와 학습 조건을 통일해 /
모델 구조에 따른 차이를 비교했습니다. /
이때 Recall은 YOLOv8s 79%, YOLO11s 80%로 / 추가 개선이 필요했습니다. /

3차 학습에서는 / 전체 객체를 23,125개로 확대하고, /
클래스당 1,306개에서 2,725개 수준으로 균형화했습니다. /
입력 크기 800픽셀, Batch 8, 100 Epoch, AdamW와 학습률 0.001을 적용하고, /
Scale을 0.2로 낮춰 과도한 변형을 줄였습니다. /
그 결과 Recall은 각각 89%와 88%까지 개선됐습니다. /

4차 학습에서는 / 3차 혼동행렬에서 확인한 취약 클래스의 미탐지 표본을 추가하고 라벨을 재점검했습니다. /
또한 과도한 증강을 줄이고 / 동일 조건 다중 Seed 반복 학습으로 재현성을 검증했습니다. /

최종 4차 결과는 / YOLOv8s와 YOLO11s의 Precision이 각각 93%와 94%, /
Recall은 91%와 90%, / mAP50은 95와 95%, /
mAP50–95는 82%와 84%를 기록했습니다. /
두 모델 모두 목표였던 Recall 90% 이상을 달성했습니다. /

[필요 시 그래프·예측 사진·혼동 행렬 탭을 차례로 선택]
각 탭에서는 학습 그래프와 실제 예측 결과, / 클래스별 정답 예측과 혼동 패턴을 확인할 수 있습니다. /


(슬라이드 10 · AI 리포트 B — YOLO26s·RT-DETR-L 학습 개선 과정)

다음은 YOLO26s와 RT-DETR-L의 학습 개선 과정입니다. /

1차 학습에서는 / 11개 클래스의 6배 증강 데이터셋과 동일한 학습·검증 분할을 적용해 /
YOLO 계열과 Transformer 계열의 기준 성능을 비교했습니다. /
이때 Recall은 YOLO26s 79%, RT-DETR-L 81%로 / 두 모델 모두 추가 개선이 필요했습니다. /

2차 학습에서는 / 11개 클래스, 총 23,125개의 균형화 데이터셋을 사용했습니다. /
두 모델 모두 입력 크기 800픽셀, Batch 4, 100 Epoch, /
AdamW와 학습률 0.001, 동일한 증강 조건을 적용했습니다. /

2차 결과에서 YOLO26s는 / Precision 92%, Recall 87%, /
mAP50 93%, mAP50–95 81%를 기록했습니다. /
RT-DETR-L은 / Precision 91%, Recall 88%, /
mAP50 92%, mAP50–95 75%를 기록했습니다. /

3차에서는 / Rope와 Styrofoam Piece 등 취약 구간을 중심으로 표본과 라벨을 다시 점검하고, /
배경으로 누락된 객체와 유사 배경의 오탐 사례를 보강했습니다. /
YOLO26s는 800픽셀, Batch 4, 최대 140 Epoch 조건으로 신규 학습했고, /
RT-DETR-L은 2차 학습 결과를 최종 비교에 그대로 사용했습니다. /

최종 비교에서 YOLO26s는 / Precision 93%, Recall 90%, /
mAP50 94%, mAP50–95 83%를 기록해 Recall 90%를 넘겼습니다. /
RT-DETR-L은 2차 결과인 / Precision 91%, Recall 88%, /
mAP50 92%, mAP50–95 75%를 기준으로 비교했습니다. /

[필요 시 그래프·예측 사진·혼동 행렬 탭을 차례로 선택]
두 모델의 학습 그래프, 예측 사진과 정규화 혼동행렬을 같은 방식으로 확인할 수 있습니다. /


(슬라이드 11 · AI 리포트 C — 최종 PT 기준 3D 비교)

다음은 네 모델의 현재 최종 사용 PT를 기준으로 구성한 / 인터랙티브 3D 비교입니다. /

현재 비교에 사용한 PT는 / YOLOv8s와 YOLO11s 4차, /
YOLO26s 3차, RT-DETR-L 2차 학습 결과입니다. /

X축은 실제 정답 클래스, / Y축은 모델이 예측한 클래스, /
Z축은 실제 클래스별 정규화 예측 비율입니다. /
점의 색상은 각각의 모델을 구분합니다. /

[그래프를 천천히 드래그해 대각선 방향이 보이도록 회전]
현재 화면은 네 모델의 최종 혼동행렬에서 / 11개 클래스의 대각선 정답 예측 비율을 중심으로 비교합니다. /
대각선 위의 점이 높을수록 / 해당 실제 클래스를 같은 클래스로 정확하게 예측한 비율이 높다는 의미입니다. /

[한 점에 마우스를 올리거나 선택]
각 점을 선택하면 / 모델 이름, 실제 클래스, 예측 클래스와 해당 비율을 확인할 수 있습니다. /
마우스 휠과 우측 확대 도구로 원하는 영역을 자세히 볼 수 있고, /
시점 초기화 버튼으로 처음 화면으로 돌아갈 수 있습니다. /

현재 슬라이드에 반영된 11개 클래스 대각선 값의 평균은 /
YOLOv8s 92%, YOLO11s 92%, YOLO26s 92%, RT-DETR-L 91%입니다. /
다만 이 값은 클래스별 정답 예측 비율을 단순 평균한 값이므로, /
전체 모델 성능은 Precision, Recall, mAP와 실제 추론 특성을 함께 봐야 합니다. /

(슬라이드 13 · 향후 확장 계획)

다음은 향후 확장 계획입니다. /

단기적으로는 / 취약하거나 표본이 적은 클래스를 보강하고, /
클래스 균형에 맞게 증강 조건을 조정한 뒤 / 동일한 미디어 조건으로 네 모델을 다시 검증하겠습니다. /
